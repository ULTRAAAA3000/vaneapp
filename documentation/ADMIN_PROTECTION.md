# Защита /admin от ботов

## Что уже было
- Отдельные логин и пароль (секреты `ADMIN_EMAIL`, `ADMIN_PASSWORD_HASH`), без паролей по умолчанию.
- Cloudflare Turnstile на входе, лимит 5 неверных попыток за 15 минут, автобан адреса после 8 неудач.
- Отдельная кука (`SameSite=Strict`, 8 часов), проверка источника запроса, журнал входов и действий.
- Общий щит API (`functions/api/lib/shield.ts`): сканеры, чёрный список, лимиты.

## Что добавлено
Админка теперь **невидима** для тех, кому там нечего делать: вместо формы входа они получают обычный 404.
- Страницы `/admin`, `/admin-hash.html` и весь `/api/admin/*` работают только на основном сайте (vaneapp.dev), на post. и studio. — 404.
- Адрес не из `ADMIN_ALLOW_IPS` — 404 (раньше было 403 «Not allowed», то есть выдавало, что админка тут есть).
- Адрес в чёрном списке, запрос без User-Agent, curl / python / Go / сканеры / headless-браузеры — 404 на странице.
- Каждая такая попытка идёт «штрафом» в щит: частые пробы приводят к блокировке адреса.

## Что сделать самому (самое сильное)
1. **`ADMIN_ALLOW_IPS`** — Cloudflare → Workers & Pages → vaneapp → Settings → Variables and Secrets → добавить значение: твои IP или сети через запятую (например `203.0.113.5, 198.51.100.0/24`). Свой IP: https://vaneapp.dev/ не покажет, откройте в браузере «what is my ip». Если IP у провайдера меняется, не включай: тогда потеряешь доступ (убрать переменную — доступ вернётся).
2. **Правило WAF** (до того, как запрос дойдёт до сайта): Cloudflare → домен vaneapp.dev → Security → WAF → Custom rules → Create: `(starts_with(http.request.uri.path, "/admin") or starts_with(http.request.uri.path, "/api/admin")) and not ip.src in {ТВОЙ_IP}` → Action: Block.
3. **Cloudflare Access** (Zero Trust, бесплатно до 50 человек): ставит вход по почте с кодом перед /admin. Это надёжнее всего, если IP плавающий.
