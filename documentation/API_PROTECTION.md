# Защита API от ботов и перебора

API Vane открыт по задумке (Zapier, Make, GPT, Claude, скрипты клиентов), поэтому «закрыть» его нельзя. Защита строится слоями:
сначала Cloudflare на границе, потом щит в коде (`functions/api/lib/shield.ts`), потом точечные лимиты на дорогих и опасных дверях.

## 1. Что делает код

### Щит перед каждым запросом `/api/*` (`shield.ts`, подключён в `functions/_middleware.ts`)

Работает **до** маршрута, базы и секретов. Всё дешёвое: счётчики в памяти, чёрный список из кэша на 15 секунд.

| Шаг | Что | Ответ |
|---|---|---|
| 1 | Только настоящие HTTP-методы (TRACE, CONNECT и экзотика отсекаются) | 405 |
| 2 | Адрес длиннее 2048 символов | 414 |
| 3 | User-Agent боевых сканеров (sqlmap, nikto, nmap, nuclei, ffuf, hydra и т. д.) | 403 + штрафные очки |
| 4 | Вход, регистрация, verify, resend, waitlist, admin login без User-Agent (браузеры его всегда шлют) | 403 |
| 5 | Адрес в «остывании» после сканирования | 429 |
| 6 | **Чёрный список на весь API** (ручные и автоматические блокировки, CIDR, ASN, страна) | 403 |
| 7 | Всплеск: больше 100 запросов за 10 секунд с одного адреса (300, если запрос с ключом Vane `cpost_` / `cvid_`) | 429 + `Retry-After` |
| 8 | Тело запроса больше 1 МБ на JSON-дверях (загрузки файлов не затрагиваются) | 413 |

Раньше чёрный список действовал только на вход, регистрацию, админ-вход и трекинг. Теперь заблокированный адрес не может ничего.

### Автоматический бан за сканирование

Сканеры оставляют следы: неизвестные пути (404), неверные методы (405), попытки открыть закрытое без cookie и без ключа (401/403).
Каждый такой ответ даёт адресу «страйк»:

- **15 страйков за минуту** → 5 минут «остывания» (429).
- **30 страйков за минуту** → автоматический бан в `ip_blocks` на `auto_ban_hours` (по умолчанию 24 ч), с причиной `scanning: …`.
  Бан виден в админке (Security → Blocks) и снимается там же. Ручные блокировки автоматика **не перезаписывает**.
- Сканер-UA даёт 10 страйков за раз: три запроса, и бан.

Не считаются страйками: 404 на `/api/media/…` (Telegram и Meta забирают наши картинки), `401` на `/api/auth/me` и `/api/auth/config`
(лендинг спрашивает «я вошёл?» у каждого посетителя), 401/403 у тех, кто прислал cookie или ключ (истёкшая сессия, неверный ключ),
429/400/200.

### Что щит сознательно НЕ делает

- **Не блокирует хостинг, VPN и дата-центры.** Zapier, Make, GPT и серверы клиентов ходят в API именно оттуда. Пресет «hosting/VPN»
  по-прежнему действует только на вход и регистрацию (как и раньше).
- **Серверы других компаний** (`/api/telegram/webhook`, `/api/channels/threads/deauthorize`, `/api/channels/threads/delete`) не попадают
  под чёрный список и правило User-Agent: они подтверждают себя секретом или подписью.
- **Загрузки** (`/api/media/upload`, `/api/video/*`, `/api/v1/video/*`) и отдача картинок (`/api/media/…`) освобождены от лимита всплеска
  и от лимита размера: у загрузок свои ограничения.
- **Локальная разработка и частные адреса** (нет заголовка `cf-connecting-ip` или адрес вида 10.x / 192.168.x / 127.x) никогда не лимитируются и не банятся.
  Сканер-UA отсекается и там, но бан не ставится.

### Точечные лимиты

- **Неверные API-ключи:** адрес, приславший больше 30 неверных (но правильно оформленных) ключей за 10 минут, получает 429. Ключ, который только что
  сработал на этом сервере, лимитом не задерживается: клиенты делят адреса (например, у Zapier), и один сломанный Zap не должен класть остальных.
- **Waitlist:** 8 записей в час с адреса (каждая запись это строка в базе, цель для спама).
- Уже были: вход, регистрация, коды из писем, создание ключей, загрузки, AI, подключение каналов, лимит на каждый ключ в минуту.

### Заголовки ответов API

Файл `public/_headers` действует только на статические файлы, на ответы Functions он не влияет. Поэтому щит добавляет к каждому ответу API
`X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` и `Cache-Control: no-store` для JSON (если не задано другое: картинки остаются кэшируемыми).

### Ограничения

Счётчики живут в памяти каждого изолята Cloudflare. Поэтому лимиты приблизительные: флуд, растёкшийся по десяткам дата-центров, считается по частям.
Для бота из одного места этого хватает, а выданный бан лежит в D1 и действует везде. Сплошную сетевую атаку (DDoS) гасит сам Cloudflare, не код.

## 2. Что включить в Cloudflare (код этого не сделает)

Dashboard → домен `vaneapp.dev` → **Security**. Доступные правила и их число зависят от тарифа, проверь в своём аккаунте.

1. **Rate limiting rule** на двери входа. Выражение: `starts_with(http.request.uri.path, "/api/auth/")`, лимит порядка 10–20 запросов
   за 10 секунд на IP, действие Block. Это отсекает перебор ещё до Pages (и до чтения D1).
2. **Custom rule «шум сканеров»**, действие Block. Выражение:
   `(http.request.uri.path contains "/wp-" or http.request.uri.path contains "/.env" or http.request.uri.path contains "/.git" or http.request.uri.path contains "/phpmyadmin" or http.request.uri.path contains "/xmlrpc" or ends_with(http.request.uri.path, ".php"))`.
   У Vane нет таких путей, сканер ищет чужие уязвимости. Это экономит запросы и чистит логи.
3. **Turnstile** на входе и регистрации уже подключён (`TURNSTILE_SITE_KEY` + `TURNSTILE_SECRET_KEY`). Проверь `https://vaneapp.dev/api/auth/config`:
   `turnstile.enabled` должно быть `true`.
4. **Bot Fight Mode: будь осторожен.** API Vane создан для автоматизации, а эта функция может показывать проверку или блокировать «подозрительно
   автоматические» запросы, то есть самих клиентов (Zapier, Make, скрипты). Если включишь, сразу проверь Security → Events: нет ли блокировок на `/api/v1/*`.
   Для защиты именно API надёжнее правила 1–2 и щит из кода.
5. **Под атакой:** Security → Settings → **Under Attack Mode** на время инцидента (он показывает проверку всем, в том числе API-клиентам, поэтому включай временно).

## 3. Как этим управлять

| Что | Где |
|---|---|
| Посмотреть и снять баны | Админка → Security → Blocks (автоматические помечены причиной `scanning: …` или `… failed sign-ins`) |
| Заблокировать адрес / подсеть / ASN / страну вручную | там же |
| Включить / выключить автобан и срок | Админка → Settings (`auto_ban`, `auto_ban_hours`) |
| **Аварийный тормоз:** щит блокирует не тех | переменная Pages `SHIELD_OFF` = `1` и редеплой. Щит отступает, остальное работает |
| Пороги | константы в начале `functions/api/lib/shield.ts` (`BURST_LIMIT`, `STRIKES_COOLDOWN`, `STRIKES_BAN`, `MAX_BODY_BYTES`…) и `BAD_KEYS_PER_WINDOW` в `apikeys.ts` |
| Смотреть, что происходит | Cloudflare → Pages → vaneapp → Functions → Real-time logs, строки `shield: banned …` |

## 4. Проверка

`npm run typecheck`, `npm run check:integrations`, `npm run test:unit`. Поведение щита покрыто набором тестов (методы, UA, чёрный список, всплеск,
страйки → остывание → бан, исключения для серверов других компаний, загрузок и общих адресов, лимиты неверных ключей и waitlist).
