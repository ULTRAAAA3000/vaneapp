# Модерация контента

Что блокируется: мат (русский, украинский, английский, транслит) в постах и в названии/описании/тегах видео; картинки и видео 18+ и с сильным насилием.

## Как работает
- **Текст** — локальный список слов (`functions/api/lib/moderation.ts`), без внешних сервисов. Понимает «х у й», «х.у.й», латинские двойники букв. Сообщение пользователю не повторяет слово.
- **Картинки** — при загрузке (`/api/media/upload`), у обложек и у ссылок на чужие картинки в посте (скачиваются и проверяются).
- **Видео в Post** — браузер берёт кадры равномерно по всей длине (по одному на ~6 секунд, от 3 до 8) и отправляет их вместе с файлом (поля `frame`). Сервер читает длину видео из файла и требует столько же кадров; меньше — отказ. Видео по ссылке с чужого сайта не принимается (его нельзя проверить, надо загрузить в Vane).
- **Видео в Studio** — после загрузки браузер отправляет кадры на `POST /api/video/videos/:id/frames` (в публичном API: `POST /api/v1/video/videos/:id/frames`). Пока видео не прошло проверку (строка в `video_checks`), его нельзя ни опубликовать, ни сделать публичную ссылку, а уже созданная ссылка не открывается. Кадр с нарушением удаляет видео из библиотеки.
- **Каждый кадр судится отдельно**, и один сомнительный кадр блокирует весь файл. Раньше все кадры уходили в OpenAI одним запросом, и результат смазывался.
- Кадры — это проверка по выборке, а не просмотр всего видео: очень короткую вставку между кадрами можно пропустить. Кадры присылает клиент, и сервер не может убедиться, что они из этого видео (в Workers нельзя декодировать видео). Полная защита — извлекать кадры на сервере (см. «Что ещё можно усилить»).

## Почему раньше проверка работала странно (и что исправлено)
1. **Любой сбой пропускал файл.** Ошибка провайдера, нераспознанный ответ модели или отсутствие ключей давали «ок, не проверено». Одно и то же видео то блокировалось, то проходило. Теперь проверка **закрывается при сбое**: три попытки с паузой, затем запасной провайдер, и если ответа всё равно нет, файл отклоняется с кодом `media_unchecked` (HTTP 503, «попробуйте через минуту»).
2. **Модель отказывалась описывать самые откровенные кадры.** Ответ «I can't help with that» не разбирался как JSON, считался сбоем и пропускался. Теперь отказ модели считается положительным ответом (нарушение).
3. **Ответ модели был случайным.** Теперь температура 0 и два узких вопроса YES/NO на кадр (нагота; жестокость) вместо одного JSON-ответа. Нагота описана подробно (обнажённая грудь, ягодицы, гениталии, прозрачная одежда, эротическое бельё); купальники на пляже, спорт и голая мужская грудь разрешены.
4. **Пороги OpenAI снижены:** `sexual` от 0.35 (было 0.5), `sexual/minors` от 0.05, `violence/graphic` от 0.4. Значения лежат в константах `SEXUAL_AT` и других в начале раздела картинок `moderation.ts`. Если появятся ложные блокировки, поднимать их надо там.
5. **В Studio видео судилось по одному кадру,** и только если браузер вообще его прислал (необязательный запрос). Теперь до 8 кадров и обязательный гейт.
6. **В Post было 3 кадра (10 %, 50 %, 90 %)**, теперь до 8 равномерно.

## Что включить (необязательно, но точнее)
В Cloudflare → Workers & Pages → vaneapp → Settings → Variables and Secrets добавить секрет **`OPENAI_API_KEY`** (ключ с platform.openai.com; endpoint модерации бесплатный). Он точнее, чем Workers AI (`llama-3.2-11b-vision-instruct`). Если ключ есть, а OpenAI не отвечает, судит Workers AI.

Если ни один провайдер не может ответить, файл **не пропускается** (раньше пропускался). `MODERATION_OFF=1` выключает всё (только для локальной разработки).

## Выкладка (порядок важен)
1. `npm run db:remote` — создаст таблицу `video_checks` (безопасно повторять).
2. `npm run db:migrate:video-checks` — один раз: видео, которые прошли старую проверку (у них есть сохранённое превью), остаются рабочими. Остальные ранее не проверялись и будут заблокированы, пока кадры не отправят (приложение делает это само при новой загрузке).
3. Деплой.

Пока `schema.sql` не запущен, публикация и ссылки в Studio отвечают «видео не проверено» (закрытый режим), поэтому шаг 1 нужен до деплоя.

## Для API
`POST /api/media/upload` с видео: multipart, поле `file` + от 3 до 8 JPEG-кадров в полях `frame` (сколько именно, зависит от длины: ~1 кадр на 6 секунд; ответ подскажет). Для Studio-видео: после `…/complete` отправить кадры на `POST /api/v1/video/videos/:id/frames`, иначе видео нельзя публиковать. Ошибки: HTTP 422 с понятным текстом при нарушении; коды текста `profanity`; медиа `media_adult`, `media_violence`, `frames_required` (мало кадров), `video_blocked` (Studio), `not_checked` (HTTP 409, видео не прошло проверку); `media_unchecked` (HTTP 503) значит, что проверка не смогла ответить, нужно повторить.

## Что ещё можно усилить
Кадры сейчас приходят от клиента. Чтобы нельзя было подсунуть чистые кадры к другому видео, нужно доставать кадры на сервере, например через Cloudflare Media Transformations (`mode=frame`, включается на зоне, платно после лимита) или Cloudflare Stream. Это отдельная настройка аккаунта, в код не входит.
